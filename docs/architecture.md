# Architecture

## Implemented inspection, mapping and export slice
`File.arrayBuffer → revisioned Worker + source digest → wasm-bindgen inspect_glb_with_mapping → rigloom-core → Inspection v2 → UI + Three.js GLTFLoader`

- rigloom-core: pure, immutable byte input. Strict GLB framing; gltf 1.4.1 schema/reference checks; explicit policy for extensions/URIs/sparse storage; buffer/accessor range checks; node tree checks; finite positions/topology; mesh/node/skin inventory; structured severity/code/path/message/remedy diagnostics.
- rigloom-wasm: accepts immutable GLB bytes and mapping overrides for inspection, or an explicit `ExportRequest` for conversion. Inspection schema 2 has optional `rig` with separate `mapping` and `binds` results; `rig: null` means structural inspection could not proceed to those checks. Export returns owned VRM bytes and a JSON report; the Worker frees the WASM result after copying them. No filesystem/network imports.
- Worker: one computation per worker. Inspection computes SHA256 over the exact input, invokes Rust and transfers the ArrayBuffer back. Export receives a copy of retained source bytes, invokes Rust and transfers the result with source/output SHA256 identities. Cancel/replacement terminates the worker (including synchronous WASM) and increments revision. Mapping revalidation also uses a fresh revision. Reading, inspecting, preparing preview and exporting are phases, not fabricated percentages.
- UI: compact toolbar, large static viewport and a single Model/Rig/Mapping/Export panel, following the owner’s #23 simplification request. Text/native controls replace decorative icons, badges and the roadmap sidebar. Light/dark themes affect the renderer background/grid too; system preference is the initial default and a manual choice persists when storage is available. Escape closes a panel and restores focus. Narrow screens stack controls below the preview. Camera views, mapping choices, explicit export metadata/permissions, downloads and text-safe diagnostics remain available. TypeScript checks saved mapping shape/source identity and presents required form fields; Rust rechecks export eligibility, metadata and confirmations. Mapping and export settings are locked during export. Main-thread glTF parsing/rendering remains a known responsiveness limitation; validation and serialization stay in the worker.
- Viewer: generation checks discard old async scene results; old scene resources are disposed. URI guard and same-origin production CSP supplement Rust's resource policy. Local blob connections are allowed for GLTFLoader image decoding; external HTTP origins remain disallowed. Browser tests monitor actual fixture network behavior.
- The retained source is not rewritten. Export creates a separate GLB with edited JSON and the original BIN chunk. No uploader, CDN, analytics, backend or shared memory is configured. The placement and experimental weight-generation contracts are described below. Inspection and conversion reports state numeric checks and limitations, not full conformance/deformation certificates.

## Mapping and existing skin contracts

`mapping::review` uses source node indices and deterministic name/alias candidates for all 55 VRM 1.0 bone keys, including 15 required keys. Ambiguous candidates stay unassigned. Explicit overrides, including `null`, take precedence. Validation checks required assignments, unique node references, scene membership and nearest mapped ancestor relationships, including optional-parent requirements. Unmapped helper nodes are allowed. This is semantic name matching, not geometric body recognition; assigning existing finger bones does not generate fingers.

`bind::validate` follows structural and binary-range validation. It checks finite affine rest/world transforms, unit quaternions, joint references/common roots, inverse-bind layout/count, relative and absolute accessor alignment, and joint/inverse-bind invertibility. Nodes cannot mix a matrix with TRS fields; explicit local matrices must be decomposable without shear. Composed world transforms and inverse binds may contain shear. Omitted inverse binds are identities; an accessor may contain more matrices than joints. Per-instance skin checks cover paired consecutive influence sets, types/counts, finite nonnegative weights, positive totals, normalization and joint indices across all sets. Existing bytes, transforms and weights remain unchanged.

The stored-pose diagnostic compares `joint_world × inverse_bind` products. A common product may be a nonidentity bind-shape transform; identity is not required. Different products produce `bind_rest_review`, because an intentional stored pose can differ from its bind pose. This is a review warning, not proof of corruption or an artist-approved neutral surface. The skinned mesh node transform is not used as a bind-matrix equality constraint. See the [glTF skin rules](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#skins).

Mapping-file schema 1 contains `source_sha256` and a complete `mapping` object from supported bone keys to source node indices or `null`. It contains no GLB data and is not project persistence. Imports require the same exact source bytes, version and complete key/value shape; Rust revalidates the restored choices. Editing/importing choices invalidates the downloadable report and mapping until validation finishes. Even an incomplete or invalid reviewed mapping can be saved to preserve work. File-load epochs, worker revisions and viewer generations prevent stale work from replacing the current selection.

## Existing-rig VRM export contract

`retained GLB + reviewed mapping + explicit metadata/confirmations → revisioned Worker → wasm-bindgen export_vrm → Rust export::export_vrm → VRM bytes + ExportReport`

The #5 implementation is merged and unreleased. Rust accepts a complete choice/null mapping for all supported humanoid keys, re-runs structural/mapping/bind checks, and requires a skinned mesh in the scene. Export eligibility does not inherit `preview_allowed`: renderer-only limits can remain warnings when the source data passes native checks.

`ExportMeta` requires a nonblank name, nonblank authors and explicit avatar/commercial/credit/modification settings plus all five boolean usage permissions. The browser starts each permission selector blank. `ExportRequest` also requires rights and source-pose confirmations, and acknowledgement of any `bind_rest_review` warning. The exporter fixes `licenseUrl` to `https://vrm.dev/licenses/1.0/`; conversion does not establish rights. T-pose, +Z facing, right-handed Y-up meters and the intended neutral pose are user assertions, not automatically verified geometry. There is no coordinate/pose rebake.

Serialization edits the original JSON value instead of rebuilding a model from Three.js objects or filtered parser types. It adds `extensionsUsed: ["VRMC_vrm"]` and a `VRMC_vrm` 1.0 root extension with metadata and source-index humanoid references. All original BIN bytes and padding remain identical. Node transforms/indices, skins, weights, inverse binds, embedded images, supported PBR resources and non-tangent morph data are retained. Mesh/morph TANGENT references are removed and counted; the accessors and binary payload remain. Tangent-only morph targets are blocked to avoid changing target indices. Empty extension lists carry no feature and are replaced/omitted; other malformed resource/relationship arrays are rejected.

Export additionally checks retained surface layouts, vertex/morph counts, alignment and finite values. The serialized output is parsed again by the pinned glTF crate. Animations/cameras retain their original data/references and are reported as unused by VRM runtimes. MToon conversion, first-person annotations, expressions, look-at, spring-bone physics and node constraints are not generated.

Native `ExportReport` schema 1 separates export eligibility, diagnostics, changes, preserved data and limitations, with source/output lengths and mapped bone count. The Worker adds source/output SHA256; blocked output has no VRM and a null output hash. Metadata/mapping edits invalidate prepared conversion files; replacing the source clears metadata/confirmations. Worker revision and source-identity checks reject stale results. Generic inspection disclaimers are kept in the downloaded report and documentation; actionable diagnostics remain accessible in the shared inspector, opening automatically on errors. Conversion details are collapsed and download actions appear only when a report is ready. A conversion report can be downloaded for a blocked native export, while browser-required fields prevent an incomplete form from starting work.

## Planned M1/M2 boundaries
`SourceDocument` retains source resources, scene/skin identifiers and source hash. `RigDefinition` stores semantic humanoid keys, parent relationships, local rest transforms and bindings. `RigEdit` records user intent in model coordinates. `SkinSolution` stores normalized influences, locked regions, algorithm/configuration and source/rig revision. `ConversionReport` separates validity, changes and deformation concerns.

The retained-resource/edit-model names above remain design contracts, not implemented structs. #4 implements `MappingReview`, `BindValidation` and source-bound mapping files; #5 implements `ExportRequest`, `ExportMeta` and `ExportReport`. The broader editable model remains #7/#10 work. Mapping decisions are stored as indices rather than renderer objects or character-specific rules. Three.js object handles stay in a renderer adapter; stable glTF indices cross the boundary.

Edit commands support undo/redo; a new source/rig revision invalidates derived weights, previews and pending worker responses. Rest pose, node transforms and inverse bind matrices must be evaluated as one coordinate system. Orientation/unit changes must propagate coherently or be rejected.

Project persistence will version source identity, mappings, transforms, placement, weights/settings and corrections. Missing source and schema migration are explicit errors. Export independently validates required VRM metadata/humanoid references and reports animation/material/resource disposition.

## Validation boundaries
Current `preview_allowed` means structural/skin checks permit a static display attempt. Mapping errors do not block an otherwise safe preview. Skin errors do. Multiple influence sets withhold preview because the current renderer only uses the first four influences. A singular skinned-mesh world transform also withholds preview through `preview_mesh_transform`: glTF ignores that node transform for skinning, but the pinned Three.js renderer inverts it and can produce invalid coordinates. Both warnings can coexist with valid bind checks. Passing does not certify a humanoid, natural deformation, complete glTF/VRM conformance or successful rendering. Loader failures retain the report. Image decoding, resource budgets and broader hostile-input hardening remain follow-up concerns.

No arbitrary size cutoff is presented as a product standard. The retained GLB, SHA256 computation, revalidation copy, WASM data, JSON report and renderer allocate memory; representative browser measurements are required before public use. A full retained source supports the implemented serializer; reconstructing from the rendered scene would lose source information.

Test-only export verification uses Ajv 8.20.0/ajv-formats 3.0.1 with pinned glTF/VRM schemas and @pixiv/three-vrm 3.5.5 with the real browser GLTFLoader and image decoder. These tools are independent of the Rust serializer. #6 additionally compares generated neutral/posed surfaces in Godot 4.5.1 with the pinned Godot VRM add-on, and tests the exact outputs in a separately built drum-vrm snapshot. These are development tools, not product imports; see [compatibility](compatibility.md) for the independent-viewer boundary and measured tolerances. They are absent from the product imports/bundle. Schema source text is downloaded by URL and SHA256 into ignored `.local/schema-cache`, not vendored. The [license audit](research/licenses.md#schema-reference-audit) records unresolved upstream terms. Schema validation does not replace semantic/reference/binary checks or certify every source model. Executed evidence belongs in validation.md against the tested commit.

Development Vite CSS injection requires an inline-style allowance only in the dev-server HTML transform. Production build CSS stays same-origin. Both modes have executed browser tests.

PR #14 review hardening: gltf-json 1.4.1 directly indexes a POSITION reference inside a validation hook, so that reference is bounds-checked before calling the parser. Empty accessor counts and the exact POSITION/index component type, dimensions and normalization are checked before native binary readers, whose assumptions are not enforced by the parser. Those #3 checks return diagnostics instead of Rust panics and remain separate from #4 mapping/skin validation. The current checks and exact tested commits are recorded in [validation.md](validation.md), the issue and PR.

## Placement foundation (#7)

Rust computes a right-handed up-axis/quarter-turn/uniform-scale/centering/floor matrix and prepared world bounds from active source instances. The viewer applies the same matrix without rewriting source bytes. A 15-joint template is an editable suggestion, not anatomical inference. World-axis TransformControls and numeric values share source-bound state; one drag is one undo command, paired edits mirror X, and frame changes reset the template while remaining undoable. Native validation rejects nonfinite/overlapping joints and invalid head/spine/leg/left-right ordering. Placement files store original SHA256, frame and joint positions; this is a narrow #10 precursor, not the broader editable-project contract. A separate revisioned Worker can be cancelled. Existing skins are excluded from this path.

## Experimental initial skin (#8)

`skinning::Request` holds the prepared frame, 15 world-space joints, method and component-to-rigid-joint overrides. Rust retains the original GLB, computes per-instance world positions, indexed topology/components and four normalized influences. It appends new accessors/BIN payload while preserving the original BIN prefix and source resources. New mesh definitions isolate instances with differing weights. A source wrapper applies the prepared frame; generated translation-only joints are separate roots. Each instance gets `inverse(jointWorld) × preparedMeshWorld` inverse binds. Native mapping/bind inspection runs again on the generated GLB, with explicit semantic indices and null optional bones to avoid source-name collisions.

Animations and morph targets are explicitly blocked only on the initial generation path; existing rig export semantics remain unchanged. All original source data stays retained in the Rig panel. Native `GeneratedSkin` crosses WASM as binary GLB plus JSON report; the worker adds its output hash. Work is cancellable by terminating that revision's worker, including output loading. After successful generation, main inspection/mapping/export targets the generated GLB. Returning to edit restores the original source report and clears generated weights and conversion downloads. Preview rotations address generated bones by parser-associated glTF indices and never mutate serialized rest data. Placement JSON schema 1 accepts optional method/rigid settings; older placement files default to surface smoothing and no overrides. It is not a complete editable project.

The default surface report now identifies `surface-v2-experimental`: a scale-relative compact-distance taper reduces remote prior influences near the skeleton, fading to the original prior far from all segments. The `segment` baseline remains v1. No source-bound placement schema changes; regeneration uses the current method implementation.

See [the initial-skin experiment](research/initial-skin.md) for the precise algorithm and unclosed quality gates. Surface smoothing is not a volume solver. Explicit component attachments do not establish inferred clothing support. The 200,000 active vertex-instance guard limits work without claiming a measured browser budget.

Joint keyboard commands are scoped to visible Rig editing and model/rig-control focus. Native form/IME/browser combinations remain untouched; movement and joint-selection shortcuts additionally require canvas focus. Nudges call the same placement edit path and mirror/invalidate identically. A held-key gesture records its initial state once, ending on key release, pointer/focus/visibility changes or window blur. Fieldset busy state and active TransformControls dragging block keyboard mutation, including the async generated-preview adoption interval. Step size is a session-only UI preference.


Camera commands belong to Viewer and require canvas focus, a loaded model and no active joint drag. They update only camera position/OrbitControls target, remain available outside Rig editing, preserve native form/IME/browser combinations and use bounded zoom/polar angles. Letter keys orbit; Shift pans in camera axes; F recenters/fits while keeping direction. View presets remain 1/2/3. No placement history or Rust semantics change.

Open example fetches one fixed same-origin, base-relative GLB through the same revisioned inspection path as local file input. A Vite plugin generates that original fixture for development and emits it for static builds; the Node fixture code is not bundled into the browser. Cancellation aborts fetch and invalidates inspection/placement revisions. Successful preparation opens Rig and focuses the canvas; switching away from Rig during preparation suppresses focus. The example is a development asset; public release/deployment remains unapproved.

## Workflow guidance (#33)

TypeScript derives a presentation-only next action from the current inspection: unskinned source → Rig, incomplete existing-rig assignments → Mapping, checked rig → Export. Structural/skin errors suppress the recommendation; Rust validation remains authoritative. Editing assignments clears the prior recommendation and export validity until reinspection. Mapping hides its assignment form for unskinned input and explains that generated bones are assigned automatically.

Preview deformation runs the existing validation/generation worker path. After a successful preview, returning to edit labels the action Update preview. Entering edit still discards generated output immediately, even without edits; placement/settings changes, cancellation and source replacement preserve the existing revision/invalidation contracts. The label resets on source replacement; no preview cache, algorithm or file-schema change is introduced. Explicit placement validation is optional under Additional checks. Human diagnostic headings/remedies precede expandable raw code/path details, which also remain in downloaded reports.

## Grouped rigid attachment (#35)

The UI groups native `Part` records by `(node, primitive)` only. A surface group is one glTF primitive in one node instance; names, proximity, shared mesh indices and material similarity never merge groups. Selecting a rigid joint expands to the exact component IDs already accepted by Rust. Deform deletes only the selected overrides. Component mode retains individual control; differing values display Mixed without choosing a replacement implicitly. Source replacement clears settings and resets selection mode. Existing placement schema 1 stores the expanded `rigid` map, so no migration or algorithm change occurs.

Three.js associates mesh primitives with their nearest glTF node ancestor to outline the selected containing surface using a disposable BoxHelper. This is a bounding box, not a component silhouette or inferred semantic region. It is hidden outside the open Initial weights editor and during computation/preview, and rebuilt after placement changes; it never enters the serialized GLB. The actual-model regression checks UI-expanded settings against an independently configured native correction, including byte parity, source-bound round trip and unchanged rest export after bending.
