# 사용자 가이드

[English](en.md) · [README](../../README.ko.md)

상태: GLB 검사·매핑·바인드 검증과 #5 기존 리그의 VRM 1.0 출력을 구현했고 릴리스·공개 배포하지 않았습니다. README대로 로컬 빌드하세요. 현재 UI는 영어이며 이 한국어·영어 문서 쌍은 같은 동작을 설명합니다.

1. **Open GLB**로 자체 포함 glTF 2.0 GLB를 선택합니다.
2. **Model**은 다음 행동을 안내합니다. 스킨 없는 휴머노이드는 **Place joints**, 기존 리그의 매핑이 불완전하면 **Review bone mapping**, 검사가 통과하면 **Prepare export**를 보여줍니다. 개수와 보고서는 **File details**, 노드 관계는 별도 접힌 항목에 있습니다. 진단은 쉬운 제목과 해결 방법을 먼저 보여주며 코드·경로는 **Technical details**에서 확인합니다. 구조·스킨 데이터 오류는 미리보기를 막습니다. 매핑 오류는 출력 전에 고쳐야 하지만 표시 가능한 모델을 숨기지 않습니다. 경고는 남은 제한을 설명합니다.
3. Front·Side·Free 시점, 드래그 회전, 스크롤 확대, 오른쪽 드래그 이동을 사용합니다. 기존 본이 있으면 겹쳐 표시합니다. 시점 버튼은 카메라만 바꾸며 모델 방향·바인드 자세를 변경하지 않습니다.
4. 검사·출력을 취소하거나 다른 파일로 교체할 수 있습니다. 이전 결과는 최신 선택을 덮어쓰지 않습니다.
5. 기존 리그는 **Mapping**에서 각 신체 부위에 해당하는 원본 본을 지정합니다. 좌우는 캐릭터 기준이며 선택 본은 미지정으로 두어도 됩니다. 스킨 없는 파일에는 빈 매핑 폼 대신 **Rig**로 가는 버튼을 보여주고, Rigloom이 만든 리그에는 매핑이 자동 지정됩니다. 필수 본은 별표로 표시하며 나머지는 **Optional bones**를 펼쳐 확인합니다. 노드 또는 **Unassigned**를 선택한 뒤 **Check assignments**를 누릅니다. 이름이 중복되어 후보가 여러 개이면 직접 선택해야 합니다. 제안은 이름과 일반 별칭을 사용하며 해부학적 위치를 자동 판별하지 않습니다.
6. **Save assignments**는 지원하는 55개 본(필수 15개)의 선택을 저장합니다. 미지정 또는 오류가 있는 선택도 검증 후 저장하여 작업을 보존할 수 있습니다. **Load assignments**는 바이트가 같은 GLB의 선택을 불러오며 다시 검증해야 적용됩니다. 변경된 GLB, 지원하지 않는 스키마, 잘못된 매핑은 거부합니다. 저장 파일은 SHA256 원본 식별값과 노드 선택을 담으며 모델 형상은 포함하지 않습니다. 원본 GLB를 보관하세요.
7. **Model → File details → Save report**는 검사·매핑·바인드·가중치 결과를 내려받습니다. 매핑을 변경하거나 불러오면 검증이 끝날 때까지 두 저장 버튼이 비활성화됩니다. 두 JSON 파일 모두 편집 가능한 프로젝트나 VRM이 아닙니다. **Dark / Light**로 UI와 3D 화면의 테마를 함께 전환합니다. 처음에는 시스템 테마를 따르고 직접 선택하면 그 값을 기억합니다. **Model / Rig / Mapping / Export** 중 하나의 패널만 열리며 선택한 버튼을 다시 누르거나 **×**, **Esc**로 닫습니다. 좁은 화면에서는 미리보기 아래에 조작부를 표시합니다. 파일·버튼은 키보드로 접근할 수 있으며 관절·카메라 단축키는 아래에서 설명합니다.

## 로컬 테스트 파일 고르기

기존 리그의 흐름은 지금 테스트할 수 있습니다: GLB 열기 → 매핑 검토 → 검증 → 출력 정보·이용 조건 입력 → VRM과 변환 보고서 저장. 직접 만들었거나 사용 권한이 있는 작은 T 자세 휴머노이드로 시작하세요. 기존 뼈대·가중치, 필수 휴머노이드 매핑 15개, 장면 하나, 내장 PNG/JPEG 텍스처가 필요합니다. 확장·압축 없이 기본 PBR을 사용하고, 입력 전에 +Z 정면·Y-up·미터 단위를 준비하세요. 파일 크기 한도는 아직 실측하지 않았습니다.

Blender에서 메시와 텍스처를 단일 glTF Binary (`.glb`)로 출력할 수 있습니다. [공식 출력 문서](https://github.com/KhronosGroup/glTF-Blender-IO/blob/main/docs/blender_docs/scene_gltf2.rst#file-format-variations)를 참고하고 결과가 아래 지원 범위에 맞는지 확인하세요. `.vrm` 입력이나 확장자만 `.glb`로 바꾸는 방법은 지원하지 않습니다. 자체 생성 출력 fixture는 조작·데이터 보존 확인용이며 해부학적 T 자세나 변형 품질 검증용이 아닙니다. 리그 없는 정적 입력은 Rig에서 관절 배치와 실험적 초기 가중치를 생성할 수 있습니다. #6 검증은 자체 생성 모델 3종을 three-vrm·별도의 Godot VRM 뷰어·고정된 로컬 drum-vrm 복사본에서 확인합니다. PR #25로 병합됐으며 실제 캐릭터 품질, 모든 뷰어 호환성, 손가락 그립, 충돌 없는 동작이나 성능 한도를 인증하지 않습니다. [호환성 검증 기록](../compatibility.md)을 참고하세요.

## 현재 지원 범위와 오류

| 입력 | 현재 동작 / 해결 방법 |
|---|---|
| 단일 장면, 여러 메시 | 허용하며 캐릭터 수를 자동 판별하지 않습니다 |
| 조밀한 삼각형 데이터, 내장 BIN, 일반적인 기본 PBR | 검사 후 뷰어로 전달하며 표시 단계에서 실패할 수도 있습니다 |
| 기존 스킨 / 스킨 없음 | 기존 스킨 데이터를 검사하고 출력 여부를 판단 / 스킨이 없는 정적 표면은 아래 Rig 흐름을 사용할 수 있습니다 |
| 누락·중복·잘못된 부모 관계의 휴머노이드 매핑 | Mapping에서 선택을 수정하세요. 매핑한 본 사이의 보조 노드는 허용합니다 |
| 잘못된 가중치·합계·관절 인덱스 또는 스킨 접근자의 형식·바이트 정렬 | 미리보기를 차단합니다. 원본 도구에서 수정하며 자동 정규화·재작성하지 않습니다 |
| JOINTS/WEIGHTS 세트가 두 개 이상 | 모든 세트를 검사하지만 현재 뷰어가 네 영향값만 사용하므로 미리보기를 보류합니다 |
| 스킨 메시 월드 변환의 역행렬이 없음 | 바인드 검사는 통과할 수 있지만 현재 뷰어가 변환을 안전하게 역산하지 못하므로 미리보기를 보류합니다 |
| 행렬과 TRS 필드 동시 사용 또는 명시적 로컬 노드 행렬의 전단 | 차단하며 원본 도구에서 로컬 변환을 수정하세요 |
| 바인드·휴지 자세 검토 경고 | 원본 자세를 확인하세요. 관절 월드 행렬 × 역바인드가 서로 다른 것은 의도된 자세일 수 있습니다. 출력에는 명시적인 확인이 필요하며 원본 바인드를 보존합니다 |
| 버퍼·이미지의 외부 URI 또는 data URI | 차단하며 버퍼를 BIN에, 이미지를 버퍼 뷰에 내장하세요 |
| 압축·특수 재질을 포함한 모든 확장 | 차단하며 기본 glTF 버전을 준비하고 원본을 보관하세요 |
| 희소 접근자 또는 삼각형 이외 형상 | 차단하며 조밀한 속성과 삼각형으로 내보내세요 |
| 빈 접근자, 잘못된 POSITION·인덱스 형식 | 보고서와 함께 차단하며 비어 있지 않은 FLOAT VEC3 위치와 부호 없는 SCALAR 인덱스를 정규화 없이 출력하세요 |
| 잘린 파일, 잘못된 참조·순환·바이너리 범위 | 차단하며 원본 도구에서 복구·재출력하세요 |
| 빈 리소스·관계 배열 또는 잘못된 표면·morph 속성 | 출력을 차단합니다. 미사용 선택 배열을 생략하거나 원본 도구에서 형식·개수·정렬·유한값을 수정하세요 |
| 탄젠트만 있는 morph 타깃 | 출력을 차단합니다. 탄젠트 참조 제외로 타깃이 사라지지 않도록 POSITION 또는 NORMAL 변위 데이터를 준비하세요 |
| 입력 애니메이션·카메라 | 정적 미리보기이며 원본 데이터는 출력 GLB 컨테이너에 유지하지만 VRM 아바타 동작으로 사용하지 않습니다 |
| FBX, PMX/PMD, BLEND | 직접 읽지 않으며 적절한 기존 도구에서 GLB로 내보내세요 |

Blender 등에서 GLB를 준비할 때 축·크기·재질·내장 텍스처·본·가중치·애니메이션을 출력 후 확인하세요. 변환 중 기능이 손실될 수 있습니다. 형식별 애드온은 각자의 라이선스가 있으며 모델 권리도 그대로 적용됩니다. 원본을 보관하세요.

역바인드는 생략할 수 있으며 이때 단위 행렬을 사용합니다. 접근자는 스킨 관절 수 이상의 행렬을 포함할 수 있습니다. 비항등 변환과 바인드 형상 변환을 보존합니다. 수치 검사 통과가 제작자가 의도한 중립 자세나 자연스러운 변형을 증명하지는 않습니다. [검증 경계](../architecture.md#mapping-and-existing-skin-contracts)를 확인하세요.

WASM 초기화가 실패하면 `npm run build` 후 새로고침하세요. WebGL이 없으면 검사·보고서는 사용할 수 있으나 미리보기에는 WebGL이 필요합니다. 로더가 실패해도 검사 보고서는 남습니다. 실측한 최대 파일 크기·정점·텍스처·본 한도나 폭넓은 브라우저 지원을 약속하지 않으며 큰 파일은 메모리를 소진할 수 있습니다. [검증 기록](../validation.md)을 확인하세요.

## VRM 1.0 출력과 보고서 읽기

1. 기존 스킨이 있는 지원 GLB를 열거나 Rig에서 스킨을 생성한 뒤 모든 휴머노이드 매핑을 검토하며 매핑·바인드 오류를 해결합니다. 출력 가능 여부와 미리보기 가능 여부는 별도입니다. 뷰어의 제한만으로 원본 스킨을 무효화하지 않습니다.
2. 상단의 **Export**에서 **Avatar name**과 **Authors (one per line)**을 입력합니다. **Version**은 선택 항목입니다. 아바타 사용 대상, 상업적 사용, 저작자 표시, 수정, 폭력적 사용, 성적 사용, 정치·종교적 사용, 반사회·혐오 사용, 재배포의 모든 이용 조건을 선택합니다. 처음에는 선택값이 없으며 권리를 추정하거나 CC0를 부여하지 않습니다.
3. 권한이 있을 때만 **I can set these usage permissions**를 확인합니다. 출력에는 선택한 설정과 [VRM Public License 1.0](https://vrm.dev/licenses/1.0/)이 적용됩니다. 원본이 +Z 방향 T 자세의 휴머노이드이며 오른손 Y-up 좌표계와 미터 단위를 사용하는지 확인합니다. Rigloom은 이 자세·방향·단위 확인을 자동 검증하거나 원본에 다시 적용하지 않습니다. 바인드 자세 경고가 나오면 검토한 뒤 해당 확인란을 선택합니다.
4. **Export VRM 1.0**을 누릅니다. Worker 처리 중에는 설정·매핑 조작이 잠기며 **Cancel**로 출력도 취소합니다. 출력이 차단되면 진단을 표시하고 VRM 없이 **Save conversion report**로 보고서를 저장할 수 있습니다.
5. **VRM ready**가 표시되면 **Save VRM**과 **Save conversion report**를 모두 저장합니다. 다운로드 버튼은 Export 패널 위쪽에 나타납니다. **Conversion details**를 펼치면 처리 내역과 제한을 확인할 수 있습니다. 보고서에는 검사·변경·보존 데이터·제한과 원본·출력 SHA256 식별값이 들어 있습니다. 메타데이터나 매핑을 변경하면 준비된 다운로드를 무효화합니다. GLB를 교체하면 메타데이터와 확인란을 초기화하며 취소·교체된 작업이 이전 다운로드를 되살리지 않습니다.

출력은 원본의 이름만 바꾼 파일이 아니라 `VRMC_vrm`을 포함한 GLB입니다. 형상·스킨 가중치·역바인드·내장 이미지를 포함한 원본 BIN 바이트를 그대로 보존합니다. 원본 노드 인덱스·계층·변환·지원하는 PBR 재질·탄젠트 이외의 morph 데이터도 유지합니다. 메시·morph의 TANGENT 참조는 제외하고 보고하지만 해당 원본 BIN 데이터는 추적을 위해 남깁니다. 탄젠트만 있는 타깃은 몰래 삭제하지 않고 차단합니다.

애니메이션·카메라의 원본 데이터와 참조는 유지하지만 VRM 런타임에서 아바타 동작으로 사용하지 않습니다. PBR을 MToon으로 변환하지 않습니다. 표정·시선·1인칭 주석·스프링 본 물리·노드 제약을 생성하지 않습니다. VRM 저장과 수치 검사 통과가 자연스러운 변형, 제작자가 의도한 올바른 중립 자세, 모든 뷰어의 호환성을 인증하지는 않습니다. [검증 기록과 제한](../validation.md)을 확인하세요.

관절 배치·실험적 가중치·기본 팔꿈치/무릎 굽힘은 아직 병합하지 않은 M2 PR에서 로컬로 사용할 수 있습니다. 전체 진단 동작·가중치 페인팅·프로젝트 복원은 후속 작업입니다. 기존 선택적 손가락 본을 매핑해도 본을 생성하거나 형상에서 손가락을 분리하지 않습니다.

## 모델 권리와 로컬 처리

업로드 서비스는 설정하지 않았습니다. 런타임 리소스는 동일 출처이며 모델 URI 리소스는 로드 전에 차단합니다. 테스트는 합성 입력을 대상으로 하며 미래의 모든 배포를 보장하지 않습니다. 개발용 출력 테스트는 고정한 업스트림 스키마를 Git 제외 캐시에 내려받고 별도의 테스트 전용 VRM 로더를 사용하며 제품에서는 이 스키마를 가져오지 않습니다. 개인 모델은 저장소 대신 git 제외 경로 `.local/`에 둡니다. 다운로드·테스트 허용이 영상 사용·재배포 허용을 뜻하지 않습니다.

공개 릴리스·배포·배포물의 모델 편입은 해당 배치의 소유자 승인이 필요합니다. [한영 릴리스 정책](../release-policy.md)을 확인하세요.

## 리그 없는 모델의 관절 배치

스킨이 없는 모델을 열고 **Rig**를 선택합니다. **Model frame**에서 위쪽 축, +Z 정면을 향한 90도 단위 회전, 원본 단위당 미터와 바닥 배치를 지정합니다. Apply frame은 새 관절 템플릿을 만들며 Undo로 이전 상태를 복구합니다. Front와 Side를 확인하면서 관절을 선택해 월드 축 핸들을 끌거나 X/Y/Z를 입력합니다. 좌우 대칭과 반투명 표시를 켜고 끌 수 있으며 Undo/Redo, Reset joint, Reset all을 제공합니다. Additional checks → Check joint placement는 유한 좌표·계층·좌우 관계를 검사하지만 해부학적으로 내부에 배치됐음을 보장하지 않습니다. Save/Load placement는 정확히 같은 원본 GLB에 연결된 배치 파일이며 전체 리깅 프로젝트가 아닙니다. 기존 스킨은 Mapping을 사용합니다. 가중치 생성은 별도 단계로 이어집니다.

## 초기 가중치 생성·테스트 (로컬, 릴리스 전)

1. 로컬 앱 주소에서 상단의 **Open example**을 누릅니다. `unrigged-standard.glb`를 열고 **Rig** 화면과 모델 키보드 포커스를 자동으로 준비합니다. 파일 선택이나 생성 명령이 필요하지 않으며, 새로 연 페이지에서는 Tab 두 번 후 Enter로도 진입합니다. 자체 생성한 거친 테스트 메시이며 제작 품질의 아바타는 아닙니다. 본인 파일은 **Open GLB**에서 **애니메이션과 morph 타깃이 없는 정적 무리그 T/A 자세 GLB**를 선택한 뒤 **Rig**를 누릅니다. 직접 만들었거나 테스트 권한이 있는 작은 모델로 시작하세요. 개발자는 `node scripts/unrigged-fixture.mjs`로 Git 제외 경로 `.local/initial-skin/`에 standard/short-wide/asymmetric 모델도 생성할 수 있습니다.
2. **Rig**에서 관절을 배치합니다. **Preview deformation**에 검증이 포함되며 별도 검사는 **Additional checks**에서 선택적으로 실행합니다. **Initial weights → Method**에서 뼈 거리 기준 방식과 실험적 표면 완화를 비교할 수 있습니다. 둘 다 가까운 신체 부위에 잘못된 영향을 줄 수 있습니다. 표면 완화는 primitive 내부 삼각형 인덱스만 따르며 UV 경계를 잇거나 옷의 부착 관계를 추론하지 않습니다. **Select by → Surface group**은 원본 표면 하나(메시 인스턴스의 primitive)에 속한 연결 조각을 묶습니다. **Target**을 고른 뒤 **Attachment → Rigid: …**로 묶음 전체를 한 관절에 고정합니다. **Connected part**에서는 조각별로 지정하고, **Mixed**는 서로 다른 설정이 섞였다는 뜻입니다. **Deform**은 선택한 범위의 고정 설정만 제거하며 다음 미리보기에서 자동 가중치를 복원합니다. 주황색 윤곽은 Connected part 모드에서도 해당 조각을 포함한 표면 전체의 경계 상자이며 정확한 실루엣이 아닙니다. 한 원본 표면에 여러 신체 부위가 들어 있을 수 있으므로 선택 범위를 확인하세요. 미지정 부품은 자동 변형하며 별도 옷은 다른 도구에서 보정해야 할 수 있습니다.
3. **Preview deformation**을 눌러 현재 배치를 검증하고 가중치를 계산합니다. 가중치는 각 관절이 표면을 얼마나 움직이는지 정하는 값이며, 관절 편집이 느려지지 않도록 명시적으로 계산합니다. Worker 상태는 검증·계산·로딩 단계를 표시하며 **Cancel**은 배치를 보존합니다. 계산에는 활성 정점 인스턴스 20만 개 제한을 두었지만 실측 성능 보장은 아닙니다. 기존 스킨은 보존하며 이 초기 생성 경로에서는 애니메이션·morph를 삭제하지 않고 차단합니다.
4. 미리보기는 편집과 분리됩니다. 좌우 팔꿈치나 무릎을 선택하고 **Angle**을 0–120도로 조절합니다. **Edit joints**는 원본 편집으로 돌아가 생성 가중치와 출력 다운로드를 폐기하므로 **Update preview**로 현재 배치·설정을 다시 계산하세요. 지금은 실제 변경 없이 편집으로 돌아가도 출력을 폐기하며 캐시로 보관하지 않습니다. 전체 동작 품질 검증이 아닌 기본 시각 점검입니다. 미리보기 굽힘은 다운로드에 굳혀 저장하지 않습니다.
5. 묶음의 고정 설정은 기존과 같은 개별 조각 ID로 배치 파일과 보고서에 저장합니다. 이전 배치 파일도 읽을 수 있고, 묶음 선택 방식 자체는 UI 설정입니다.
6. **Save rigged GLB**는 생성한 휴지 자세 리그를 저장합니다. **Save weight report**에는 원본/출력 해시, 축·관절, 알고리즘, 부품 고정과 수치 검사 결과가 들어 있습니다. 편집 모드의 **Save placement**에는 원본 해시·배치·가중치 설정이 들어가며 원본 GLB도 보관해야 합니다. 전체 프로젝트 파일은 아닙니다.
7. VRM은 **Export**에서 위의 명시적 메타데이터·이용 조건 절차로 출력합니다. 준비한 표면은 +Z 정면·Y-up·미터 단위 T 자세여야 합니다. A 자세에서 관절을 배치하거나 미리보기로 굽혀도 메시를 T 자세로 재작성하지 않습니다. 수치 검사 통과가 자연스러운 변형·옷·손·모든 뷰어 호환성을 인증하지는 않습니다.

## 관절 편집 단축키

편집 모드에서 **Rig**를 열고 모델을 클릭하거나 **Keyboard shortcuts → Focus model**을 누릅니다. 카메라 방향과 관계없이 준비된 **월드 축**으로 이동합니다. 처리 중·마우스 핸들 드래그 중·생성 결과 미리보기에서는 작동하지 않습니다. 입력창·선택 상자는 기본 편집과 IME 동작을 유지하며 Rig를 닫으면 이 단축키도 비활성화됩니다.

| 키 | 동작 |
|---|---|
| ⌘/Ctrl+Z | 관절 배치 실행 취소. Rig 버튼에 포커스가 있어도 사용 가능 |
| ⌘/Ctrl+Shift+Z, Ctrl+Y | 관절 배치 다시 실행 |
| ← / → | −X / +X |
| ↓ / ↑ | −Y / +Y |
| Option(Alt)+↓ / ↑ | −Z / +Z |
| 이동 키와 Shift | 선택한 이동 간격의 1/10로 미세 이동 |
| [ / ] | 이전 / 다음 관절. 끝에서 반대쪽 끝으로 순환 |

기본 간격은 준비된 미터 좌표계의 **1 cm**입니다. **Keyboard shortcuts → Move step**에서 1 mm·1 cm·10 cm를 선택합니다. 이동 키를 길게 누른 동작은 한 번의 실행 취소로 되돌리며, 키를 놓거나 포커스가 바뀌면 묶음을 끝냅니다. 키보드 이동도 드래그·좌표 입력과 같은 대칭·이력·출력 무효화 경로를 사용합니다. 이동 간격은 현재 세션의 설정이며 배치 JSON에는 저장하지 않습니다. 가중치나 미리보기 자세가 아닌 관절 배치를 편집합니다.

## 카메라 단축키

모델을 클릭하거나 미리보기 위의 **View keys → Focus model view**를 선택해 포커스를 줍니다(Tab/Enter도 가능). **Open example**은 자동으로 포커스를 줍니다. 영문 입력 상태에서 사용하세요. 모델이 열려 있으면 가중치 미리보기나 Rig 패널을 닫은 상태에서도 동작합니다. 입력칸·IME·Cmd/Ctrl/Alt 조합은 기본 동작을 유지하며, 관절 핸들을 드래그하는 동안은 카메라 키를 막습니다. 카메라 조작은 관절·가중치·관절 Undo 기록을 바꾸지 않습니다.

| 키 | 동작 |
|---|---|
| + 또는 = / − | 확대 / 축소(Cmd/Ctrl 없이) |
| I / K | 위 / 아래로 시점 회전 |
| J / L | 좌 / 우로 시점 회전 |
| Shift+I/K/J/L | 화면 축 기준 위/아래/좌/우로 카메라 중심 이동 |
| F | 바라보는 방향을 유지하며 모델 중앙에 전체 맞춤 |
| 1 / 2 / 3 | 정면 / 측면 / 자유 시점으로 전환하고 전체 맞춤 |

전체 흐름은 **Open example → 관절 선택·이동 → Preview deformation → Bend/Angle → Edit joints → Update preview**입니다. 모델에 포커스가 있을 때 **[ / ]**로 관절을 선택하고 방향키로 이동합니다. 나머지 컨트롤은 Tab으로 이동해 기본 키보드 동작을 사용할 수 있습니다. 새로고침은 저장하지 않은 편집을 복원하지 않으므로 나가기 전에 Save placement로 저장하고, 같은 원본을 다시 열어 배치 파일을 불러오세요.

### 현재 가중치 품질

표면 방식은 `surface-v3-experimental`을 사용하며, 표면 완화 후 먼 관절의 영향을 제한합니다. 이전 표면 방식 배치 파일을 다시 생성하면 현재 알고리즘이 적용되므로, 정확히 같은 이전 결과가 필요하면 당시 리깅 GLB와 보고서를 보관하세요. 공식 로컬 샘플 두 개에서 v2 대비 평균 굽힘 오차가 소폭 감소했으나, 일부 어깨 오차와 한 샘플의 표면 변형 오차 지표는 증가했습니다. 눈에 띄는 자연스러움 개선을 뜻하지 않으며, 주름·부피 손실·장식의 잘못된 움직임은 남아 있습니다. 내보내기 전에 어깨·팔꿈치·엉덩이·무릎을 정면과 측면에서 확인하세요. 15관절 생성기는 리그 없는 휴머노이드용이며, 사족보행 모델이나 기존 애니메이션 리그를 대체하는 입력으로 사용할 수 없습니다. [실제 모델 검증 결과와 한계](../verification/surface-support-2026-10-26.md)를 참고하세요. 모델과 로컬 테스트 파생 파일은 제품에 포함하지 않습니다.
