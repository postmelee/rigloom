# 검사·미리보기 문제 해결

먼저 **Diagnostics**의 `code`, `path`, 설명과 해결 안내를 확인하세요. 보고서가 생성되었다면 **Save report**로 보관할 수 있습니다. 필드의 의미는 [검사 보고서 참조](../reference/inspection-report.md)에 있습니다.

## 지원하지 않는 GLB 구조

`resource_uri`는 버퍼나 이미지가 URI를 사용한다는 뜻입니다. 원본 도구에서 버퍼는 GLB의 BIN에, 이미지는 버퍼 뷰에 내장해 다시 출력하세요. `data:` URI도 지원하지 않습니다.

`unsupported_extension`은 압축·특수 재질 등을 위한 확장이 선언되었거나 사용되었다는 뜻입니다. 원본을 보관하고 확장 없는 기본 glTF 버전을 별도로 준비하세요. 확장을 제거하면 표현이나 기능이 달라질 수 있으므로 결과를 비교해야 합니다.

`sparse_accessor`·`accessor_storage`는 조밀한 속성 데이터로, `primitive_mode`는 삼각형으로 다시 출력하면 해결할 수 있습니다. `accessor_count`·`position_layout`·`index_layout`은 빈 데이터나 잘못된 형식을 나타냅니다. [지원 입력 조건](../reference/supported-inputs.md)을 원본 도구의 출력 설정과 대조하세요.

`invalid_glb`·`invalid_gltf`, 범위·참조·계층 진단은 원본 파일을 복구하거나 다시 출력해야 합니다. 보고서에서 가리키는 위치를 확인하고 원본 도구의 검증기를 함께 사용하세요. 파일 확장자만 `.glb`로 바꾸는 것으로는 변환되지 않습니다.

## 검사기는 통과했지만 화면이 나오지 않음

- WebGL을 사용할 수 없으면 브라우저의 WebGL 설정을 확인하세요. 파일 검사와 보고서 저장은 계속 사용할 수 있습니다.
- `Preview failed`가 나오면 보고서를 저장하고 원본 도구에서 장면·이미지·재질을 점검하세요. 검사 통과가 로더의 모든 동작을 보증하지는 않습니다.
- Worker 또는 WASM 초기화가 실패하면 로컬 저장소에서 `npm run build`를 실행한 뒤 새로고침하세요.
- 큰 파일에서 멈추거나 탭이 종료되면 더 작은 파일로 문제를 좁히세요. 현재 실측한 최대 파일 크기·메모리 예산은 없습니다.

검사 도중 **Cancel inspection**을 누르거나 다른 파일을 선택하면 이전 작업을 취소할 수 있습니다. 결과가 나온 뒤 새 파일을 열면 새 검사가 시작됩니다.

## 파일 준비 시 확인할 점

FBX·PMX/PMD·BLEND는 직접 읽지 않습니다. 해당 형식을 다루는 도구에서 GLB로 내보내고 축·크기·재질·텍스처·본·가중치·애니메이션을 비교하세요. 변환 도구와 애드온의 라이선스는 각각 확인해야 합니다. 다운로드·테스트 권한이 영상 사용이나 재배포 권한까지 포함하지는 않습니다.

문제가 계속되면 [이슈](https://github.com/postmelee/rigloom/issues)에 재현 순서, 브라우저·환경, 진단 코드를 기록하세요. 모델과 보고서에 개인정보나 비공개 이름이 포함될 수 있으므로 공유 전에 내용을 확인하고, 가능하면 직접 생성한 최소 예제를 사용하세요.
