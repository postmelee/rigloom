# 문서의 책임과 유지보수

Rigloom은 [Diátaxis](https://diataxis.fr/)의 독자 목적 구분과 [Hyper Waterfall v0.3.0](https://github.com/postmelee/hyper-waterfall/tree/v0.3.0)의 작업 기록 구조를 사용합니다. 폴더 이름을 맞추려고 내용 없는 미래 기능 문서를 만들지 않습니다.

## 내용의 기준 위치

| 내용                            | 기준 위치                         | 갱신 시점                           |
| ------------------------------- | --------------------------------- | ----------------------------------- |
| 제품 소개·시작·탐색             | 루트 README                       | 사용 가능한 기능·시작 방법 변경     |
| 학습 경험                       | docs/tutorials                    | 실제 따라 할 수 있는 예제가 바뀔 때 |
| 목표 달성·문제 해결 절차        | docs/how-to                       | 명령·사용 절차가 바뀔 때            |
| 지원 형식·필드·진단 사실        | docs/reference                    | 구현의 지원 범위·출력 계약 변경     |
| 개념·이유                       | docs/explanation                  | 이해에 필요한 모델이 바뀔 때        |
| 목표·수용 기준·장기 설계        | specs/product, architecture       | 승인된 설계 변경                    |
| 채택 결정과 대안                | specs/decisions                   | 새 선택·기존 선택 대체              |
| 상시 정책                       | specs/policies                    | 승인된 권한·운영 기준 변경          |
| 실행할 작업과 진행 상태         | GitHub 이슈·PR                    | 실제 실행·검증·리뷰·병합            |
| 날짜·이슈별 계획·승인·증거·조사 | mydocs 역할별 폴더                | 해당 작업 단계                      |
| 프레임워크 운영 절차            | mydocs/manual, _templates, skills | 별도 framework 업데이트 작업        |

다른 문서는 이 기준 위치를 링크합니다. README에 검사 횟수·브랜치·다음 작업 승인 로그를 누적하지 않습니다. specs의 계획을 docs의 현재 사용법으로 옮길 때는 구현과 검증 근거가 있어야 합니다. 병합과 공개 배포도 구분합니다.

## 문서를 추가하거나 옮길 때

- 독자, 목적, 확정 수준과 수명을 먼저 정합니다. 한 문서의 주된 목적을 하나로 유지하고 다른 목적은 링크합니다.
- 각 디렉터리 README는 담당 범위와 탐색 링크만 제공합니다. 하위 AGENTS는 상위와 다른 추가 규칙만 담습니다.
- 한국어 단일 문서를 유지합니다. 코드 식별자·명령·법적 고지·출처 원문·기계 판독 데이터는 정확한 원문을 보존합니다.
- 이동하는 PR에서 내부 링크와 인덱스를 갱신합니다. 외부 옛 경로의 호환 여부를 보고하고 큰 이동은 이전 경로→새 경로 표를 남깁니다.
- 오래된 실행 기록은 당시 날짜와 commit을 유지합니다. 과거 계획을 새 승인으로 재해석하거나 실행하지 않은 검사를 통과로 만들지 않습니다.

실행 절차와 파일명은 [문서 구조 매뉴얼](../../mydocs/manual/document_structure_guide.md)을 따릅니다. `mydocs/manual`에는 제품 설명이나 개별 PR의 히스토리를 넣지 않습니다.

## Hyper Waterfall 업데이트

공식 매니페스트·locale 원본과 [버전 기록](../../.hyper-waterfall/version.json)을 먼저 비교합니다. 설치 파일을 편의상 포맷하거나 요약하지 않습니다. 프로젝트별 규칙은 AGENTS의 지정 구역에만 두고, upstream 업데이트가 로컬 변경을 덮어쓰지 않는지 검토합니다. 버전 기록의 `rigloomInstallation` 해시는 최초 설치 기준이며 이후 승인된 AGENTS 수정의 현재 해시를 뜻하지 않습니다. 원본 라이선스는 [제3자 고지](../../THIRD_PARTY_NOTICES.md)에 보존합니다.
