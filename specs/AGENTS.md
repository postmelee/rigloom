# 설계 문서 작성 규칙

이 규칙은 `specs/`에 적용하며 [루트 규칙](../AGENTS.md)을 보완한다.

- 요구사항과 설계의 권위 근거를 보관한다. 실제 사용 절차는 `docs/`, 이슈별 계획·승인·검증 결과는 `mydocs/`로 분리한다.
- 요구된 동작, 채택된 설계, 실제 구현을 명시적으로 구분한다. 로드맵의 순서는 구현 권한을 부여하지 않는다.
- 아키텍처를 변경하면 현재 경계와 관련 ADR을 함께 갱신한다. 과거 결정은 삭제하지 않고 후속 결정과 연결한다.
- 마일스톤 문서에는 목표·수용 기준·의존 관계를 둔다. 가변적인 이슈 상태는 GitHub를 참조한다.
- 각 하위 디렉터리 README는 담당 범위와 문서 탐색만 제공한다. 상위 정책이나 전체 본문을 복제하지 않는다.
- 한국어로 작성하되 코드 식별자, 명령, 버전, 라이선스 원문은 정확히 유지한다.
