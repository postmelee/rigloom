사용자의 학습·문제 해결·참조·이해 목적과 개발자가 따르는 요구사항·설계를 분리한다.

## 본문 변경 정도 / 본문 무손실 여부

문장은 한국어로 통합·재작성했다. 기존 영문/한글 guide와 요구사항을 대조하여 지원 제한, 미구현 기능, 자산·품질 기준을 보존했다. 두 Mermaid는 사용자 처리 흐름과 구현/계획 경계를 각각 설명한다. 제품 소스는 바꾸지 않았다. 기존 중복 문서 삭제와 과거 기록 이관은 Stage 2에서 수행한다.

## 검증 결과

- `git diff --check`: 통과.
- UI 버튼·상태·다운로드 이름, Rust 보고서 필드/진단·지원 범위를 소스와 대조했다.
- 생성 fixture의 surface는 메시 1·정점 3·스킨 0, external은 외부 URI를 포함함을 확인했다.
- 개발/검증 명령을 package.json, Rust toolchain, Playwright 설정, CI와 대조했다.
- 요구사항·아키텍처·ADR·정책을 이전 문서와 읽기 검토했다. 브라우저 또는 엔진 회귀 검사를 이번 단계에서 새로 실행하지 않았다.

## 잔여 위험

mydocs 이동 대상과 새 프로젝트 인덱스 링크는 Stage 2 완료 후 연결된다. Mermaid 구문·모든 상대 링크·Markdown 형식은 Stage 3에서 통합 검증한다.
