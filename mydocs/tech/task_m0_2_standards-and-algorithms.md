# 표준·알고리즘 도입 조사

조사 기준일: **2026-10-24**. 이관일: **2026-10-25**. 기존 `docs/research/standards-and-algorithms.md`의 조사 결과를 한국어로 이관했으며 새 외부 조사나 알고리즘 실험을 수행한 기록이 아니다. [#2](https://github.com/postmelee/rigloom/issues/2)의 도입 전 확인 조건은 여전히 남아 있다.

## 배경과 조사 질문

GLB 검사·VRM 변환에 참고할 표준과 독립 구현, M2 스키닝 후보의 품질·성능·라이선스 조건을 구분한다. 무엇을 이미 채택했는지, 무엇이 검증 후보인지, 실제 도입 전에 어떤 근거가 필요한지를 기록한다.

정확한 외부 저장소 리비전과 GitHub 라이선스 **메타데이터**는 [원본 스냅샷](task_m0_2_source-snapshot.json)에 있다. 메타데이터만으로 파일·모듈별 라이선스 감사를 완료할 수 없다. `pushed_at`은 조사 시 비교용 정보이며 유지보수나 품질의 보증이 아니다. 아래 링크는 참고 자료이며 해당 구현·에셋을 저장소에 복사했다는 뜻이 아니다.

## 표준과 구현 참고 자료

| 자료 | 결정 또는 도입 전 확인 조건 |
|---|---|

| [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) | GLB 포장, 장면, 버퍼·접근자, 스킨·변환을 참고한다. GLB라는 사실만으로 모든 리소스가 내장되어 있지는 않다. 첫 검사 구현은 URI 리소스와 확장을 명시적으로 차단한다. |
| [gltf 1.4.1](https://docs.rs/gltf/1.4.1/gltf/) / [gltf-json 1.4.1](https://docs.rs/gltf-json/1.4.1/gltf_json/) | 기본 import/image 기능 없이 gltf를 채택했다. gltf-json은 간접 의존성으로 스키마를 지원한다. 추가 바이너리·정책 검사는 Rigloom 책임이며 파싱 성공은 스키닝 품질 인증이 아니다. |
| [wasm-bindgen](https://wasm-bindgen.github.io/wasm-bindgen/) | 바이트 입력과 문자열 보고서를 연결하는 고정 버전을 채택했다. 처음에는 한 개의 Worker를 사용하며 스레딩·격리 조건을 당연한 전제로 삼지 않는다. |
| [Three.js](https://threejs.org/docs/) | 고정 버전의 렌더러와 기본 GLTFLoader를 채택했다. 변환의 기준은 렌더러가 소유하지 않는다. 번들·메모리 크기는 작다고 추정하지 않고 측정해야 한다. |

| [VRM Add-on for Blender](https://github.com/saturday06/VRM-Addon-for-Blender) | 독립 뷰어·출력 참고 후보다. 코드를 복사하지 않았으며 실제 사용 시 릴리스·버전·환경을 기록해야 한다. |

| [MMD Tools](https://github.com/MMD-Blender/blender_mmd_tools) | 향후 오프라인 입력 준비 경로 후보로만 다룬다. GitHub 메타데이터는 GPL이며 코드를 복사하거나 포함하지 않았다. 모델 이용 권리는 별도다. |

표에 나타났다는 이유만으로 추가 참고 라이브러리를 채택하지 않는다. 실제 사용한 패키지·선언 라이선스는 [의존성 조사 대장](task_m0_2_licenses.md)과 [해결된 의존성 스냅샷](task_m0_2_dependencies.json)을 확인한다.

## 스키닝 후보 — 미구현

| 방법 | 조사 이유 | 실패 가능 조건과 채택 전 검증 |
|---|---|---|
| 본 선분까지 거리와 가중 혼합 | 작고 결정적인 Rust 기준 구현과 빠른 피드백 | 가까운 팔다리·몸통으로 가중치가 새어 나갈 수 있다. 허벅지 옆 손, 어깨·사타구니 분리를 검증한다. 최근접 본 결과를 최종 품질로 간주하지 않는다. |
| 표면 연결성·측지 거리 확산 | 유클리드 거리로 인한 영향 누출을 줄일 가능성 | 분리된 옷·눈·장비는 명시적 부착 관계가 필요하다. 열린 표면과 메시 위상이 중요하다. 선택 전에 자체 fixture로 비교한다. |
| 열·체적 기반 가중치 | 내부에서 부드러운 영향 분포를 만들 후보 | 닫힘, 구멍, 얇은 부위, 복셀 해상도, 솔버 메모리·수치 동작을 측정해야 한다. 전제 미충족은 진단하며 조용히 형상을 복구·삭제하지 않는다. |

### libigl

[libigl 튜토리얼](https://libigl.github.io/tutorial/)은 형상·가중치 연구 자료이며 Rust/WASM에서의 실행 가능성을 증명하지 않는다. 저장소에는 라이선스가 다른 코드 영역이 있고, 조사 스냅샷의 집계 메타데이터는 GPL-3.0이다. 이 값만으로 모든 모듈이 같은 라이선스라고 판단하거나 MIT와 호환된다고 간주하지 않는다. 선택할 모듈과 선택적 솔버 의존성의 실제 파일·라이선스를 각각 확인해야 한다. libigl 소스를 복사하거나 링크하지 않았다. 논문에서 독립적으로 구현하더라도 별도의 수치 검증이 필요하다.

### Pinocchio

[Baran·Popović, Automatic Rigging and Animation of 3D Characters, SIGGRAPH 2007 — MIT 기록](https://dspace.mit.edu/entities/publication/02216671-1424-4552-a2d3-74cec29e2062)은 Pinocchio 연구의 참고 자료다. 2026-10-24 조사에서는 저자의 원본 소스 URL을 웹 도구로 열지 못했다. 원본 구현의 출처, 라이브러리·데모·솔버의 개별 라이선스와 의존성은 확인되지 않았다. 미러나 논문만 보고 코드 이용 권한을 추정하지 않는다.

소스·학습 데이터·가중치·데모 에셋은 채택하지 않았다. 논문의 결과에서 최신 브라우저 실행 시간을 추정하지도 않았다.

## 가중치 방법 채택 전에 필요한 증거

직접 생성한 연결·분리 메시와 자세로 긴 팔·짧은 다리, 비대칭, 얇거나 열린 형상, 허벅지 옆 손, 겨드랑이·사타구니, 겹친 옷, 단단한 부품, 작은 손발을 다룬다. 알고리즘·설정·원본 해시·정점·텍스처·본 개수·CPU·브라우저·경과 시간·최대 메모리 측정 방법을 기록해야 한다.

가중치가 유한·비음수·정규화되었는지, 인덱스가 유효한지, 비어 있는 가중치가 없는지, 중립 자세가 보존되는지, 결과를 재현할 수 있는지 확인한다. 단순 기준 방법, 품질 후보 방법, 기존 도구의 기록된 출력을 비교한 뒤 M2 채택 여부를 판단한다.

## 비결정과 적용 영향

스키닝 방법 선정, 원본 Pinocchio 구현·개별 모듈 라이선스 확인, 독립 VRM 로더·뷰어 검증과 실제 모델 성능 측정은 이 조사만으로 완료되지 않았다. Hyper Waterfall 도입 기록은 [별도 버전 파일](../../.hyper-waterfall/version.json)에서 관리하며, 문서 재편이나 프레임워크 도입은 이 연구의 미해결 조건을 해소하지 않는다. 채택한 설계의 기준은 [제품 요구사항](../../specs/product/requirements.md)과 해당 ADR에 반영하고, 미채택 후보는 이 조사 기록에 남긴다.
